Brand Copilot · GetCrux AI Hackathon · 17 Oct 2026

An agent that designs on a real canvas, then checks its own work

A chat copilot inside a Polotno editor. It reads the canvas as structured data, looks at the rendered pixels, plans edits with a text model, renders deterministically, and loops through brand lint and visual QA until the checks pass. Everything it does streams into the chat as an expandable step trace.

4 models, each with one job 16 deterministic brand rules 11 visual QA checks per render 5 fix rounds before it stops 2 tenants: Xero and GetCrux
One request, end to end

The loop behind every message

Click a step. The same loop runs for a blank-page brief, an edit to a selected element, a reference-based batch, a winner iteration and a brand-scan remake. Only the first and last steps differ.

↻

Why it converges. Every path ends in the same validator. Lint errors are auto-fixed on the server mirror before the page reaches the editor, the report card shows what changed and why, and visual QA re-renders the real page and sends the defects back as the next planning input. If a fix round returns the same defects, the loop stops and says so instead of burning rounds.

Who does what

  "selectedIds": ["t_head"] },
  "pages": [{ "id": "p1", "background": "#000856", "elements": [
    { "id": "card1", "type": "figure", "role": "card", "x": 72, "y": 300, "w": 936, "h": 420 },
    { "id": "t_head", "type": "text", "container": "card1", "text": "Your books, now on autopilot.",
      "x": 120, "y": 348, "w": 840, "h": 112, "fontSize": 56, "fill": "#000856" },
    { "id": "cta", "type": "text", "group": "cta_pill", "text": "Find out more" … },
    { "id": "logo", "role": "logo", "assetId": "logo-white", "x": 72, "y": 64, "w": 240, "h": 69 }
  ] }] }
  • Ids and boxes for every element, so an edit can target one thing precisely.
  • Roles, containers and groups (card, cta pill, logo) so moving a card moves its contents.
  • Selection, so "make this bigger" means the selected element.
  • Snapshot of the active page, rendered by the editor itself, for the vision pass.
Output: ops on ids, with a reason
update_design({
  "pageId": "p1",
  "rationale": "Logo straddles the card edge; move it to the free top-right corner and tighten the headline.",
  "ops": [
    { "op": "set", "id": "logo",   "props": { "x": 768, "y": 64 } },
    { "op": "set", "id": "t_head", "props": { "text": "Books that close themselves." } },
    { "op": "raise", "id": "logo" }
  ]
})
// server: apply to mirror → re-measure text → restack card → lint → auto-fix → stream ops to editor
  • Four verbs: set, add, delete, raise. Nothing is regenerated as pixels.
  • Rationale is mandatory, and it is what the trace shows under "why".
  • Text is re-measured with the brand font before anything lands, so longer copy never overlaps the button.
  • The editor applies the same ops, so undo works and the user can keep editing.

Code map

Every request, function by function

Paths are relative to the repo. Green hops run in the browser, violet hops call a model, the rest is deterministic server code. Expand a flow to follow it from the click to the pixels.

Three models at run time, one more at onboarding. DeepSeek-V4-Pro is the only text-to-text model and the only one that plans or writes layout. gpt-4.1 is image-to-text everywhere: reference briefs, render inspection, brand scans, and reading guideline PDFs during onboarding. gpt-image-1 is the only text-to-image model and runs only when the asset library has nothing that fits. Onboarding tags assets with gpt-4.1-mini, the cheap sibling of the same vision model, because tagging 90 assets with the big one is wasted money.
Transport: NDJSON over HTTP, both ways

One POST /api/agent opens a chunked response. The server writes one JSON object per line the moment each event happens, so the chat updates in real time without polling. It is not Server-Sent Events: SSE is GET-only and one-directional, and this run needs to carry a 40 MB body in and ask the editor questions on the way.

Bidirectional works like this. When the server needs something only the browser has, it writes a request event with an id and awaits a promise in server/src/agent/snapshots.ts. The editor answers with a tiny POST to a reply endpoint, which resolves that promise. The run continues on the same stream. Closing the tab aborts the run through the response's close handler.

Quality gate

What has to pass before it says done

Two layers. The lint engine is code and catches geometry and brand facts exactly. Visual QA is a model looking at the real render and catches what geometry misses: a charm covering a face, a headline that reads badly, a layout that just looks wrong.

Layer 1 · deterministic lint, auto-fixable
PaletteEvery fill and text colour is in the brand kit
FontsOnly brand faces and weights
Logo present, sized, right colourwayWhite on dark, colour on light; clear space respected
Logo hidden or overlapping a cardRaised to top, or moved to the nearest free corner
ContrastWCAG 3:1 for large text, best-contrast palette pick as the fix
Text overlap, text over buttonMeasured with real font metrics, restacked inside the card
Image over text, image cut offImagery never sits under copy or past the canvas
Card contents, on-canvasChildren stay inside their container; nothing leaves the page
Edges, safe zonesMargins and Meta-safe bands for Stories
Text size, ragged alignmentMinimum legible size; left edges snapped to the column
Tone and CTABrand voice words, one clear call to action
Logo distortedAspect ratio locked to the asset
Layer 2 · visual QA on the real render

Eleven questions the vision model answers about the pixels

  1. Occlusion: anything covering a logo, face or text?
  2. Clipping: any element cut by the canvas edge?
  3. Visibility: anything too faint or too small to read?
  4. Containment: card contents inside their card?
  5. Overlap: text on text, text on imagery?
  6. Alignment: ragged edges, uneven gaps?
  7. Readability: line breaks, widows, contrast in context
  8. Image quality: blur, stretching, odd crops
  9. Placement: logo in a corner, CTA where eyes land
  10. Composition: balance, breathing room, hierarchy
  11. Brand sense: does it look like this brand?
